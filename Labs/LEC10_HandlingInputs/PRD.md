# 소년 캐릭터 입력 처리 및 애니메이션 개발 문서

## 1. 목적 및 기준

`PRE_PRD.md`를 바탕으로 방향키로 소년 캐릭터를 움직이는 프로그램을 만든다. 이동 여부에 따라 이동/IDLE 애니메이션을 전환하고, 세로 이동 시 마지막으로 바라본 좌우 방향을 유지한다. 캐릭터 전체가 화면 안에 표시되도록 이동 경계를 제한한다.

초안에 명시된 요구사항을 우선한다. 화면 크기, 속도, 동시 입력 처리 등 초안에 없는 사항은 이 문서의 개발 기준을 적용한다. 애니메이션 좌표와 프레임 수는 실제 이미지 분석 후 확정한다.

## 2. 개발 범위 및 산출물

| 항목 | 요구사항 및 개발 기준 |
| --- | --- |
| 언어 및 라이브러리 | Python, pico2d |
| 실행 파일 | `Labs/LEC10_HandlingInputs/move_charcter_viewer.py` 한 파일 |
| 배경 이미지 | 같은 폴더의 `TUK_GROUND.png` |
| 스프라이트 시트 | 같은 폴더의 `animation_sheet.png` |
| 화면 크기 | 기존 LEC10 예제에 맞춰 800×600픽셀을 초기 기준으로 사용 |
| 이동 입력 | 상하좌우 방향키 |
| 재생 방식 | 현재 상태에 맞는 애니메이션을 계속 반복 |
| 개발 방식 | 단계별 구현으로 최소 20회의 실제 개발 커밋 |
| 커밋 메시지 | 한국어로 작성 |

파일명 `move_charcter_viewer.py`는 초안의 철자를 그대로 사용한다. 코드, 프레임 메타데이터, 입력 및 상태 처리는 이 파일에 작성한다. 기존 실습 파일은 참고 자료로 활용한다.

LEC09의 동작별 5회 반복과 1초 대기 방식은 이 프로그램에 적용하지 않는다. LEC10은 방향키 입력에 따라 애니메이션이 즉시 전환되어야 한다.

## 3. 기능 요구사항

### FR-01. 초기화 및 이미지 로딩

- `open_canvas(800, 600)`으로 화면을 연다.
- 이미지 경로는 실행 파일 위치를 기준으로 계산한다.
- 배경을 화면 전체에 표시하고 캐릭터를 그 위에 그린다.
- 캐릭터는 화면 중앙에서 오른쪽을 바라보는 IDLE 상태로 시작한다. 초기 방향은 개발 기준이다.
- 이미지 누락 또는 로딩 실패 시 파일명과 원인을 알 수 있는 오류 메시지로 종료한다.

### FR-02. 상하좌우 이동

- 방향키를 누르고 있는 동안 해당 방향으로 이동하고, 키를 놓으면 해당 방향 입력을 해제한다.
- 이동 거리는 경과 시간에 비례하도록 계산한다. 초기 이동 속도는 초당 200픽셀로 설정하고 상수로 조정할 수 있게 한다.
- 대각선 입력은 허용하며 벡터를 정규화해 직선 이동과 같은 속도를 유지한다.
- 좌우 또는 상하 반대 키를 함께 누르면 해당 축 입력을 상쇄한다.
- 눌린 키를 집합으로 관리해 운영체제의 반복 KEYDOWN 이벤트가 이동 속도에 영향을 주지 않게 한다.
- 창 포커스를 잃으면 눌린 키 상태를 초기화해 키를 놓았는데 계속 이동하는 현상을 방지한다.

### FR-03. IDLE 애니메이션

- 이동하지 않을 때 현재 바라보는 방향의 IDLE 애니메이션을 반복 재생한다.
- 방향키를 모두 놓거나 반대 입력이 상쇄되어 위치가 변하지 않으면 IDLE 상태로 전환한다.
- 경계에 막혀 실제 위치가 변하지 않을 때도 IDLE 상태를 사용한다. 경계를 따라 다른 축으로 이동할 수 있으면 이동 상태를 유지한다.
- 이동에서 IDLE로 바뀔 때 해당 애니메이션의 첫 프레임부터 재생한다.

### FR-04. 이동 애니메이션 및 좌우 방향

- 오른쪽 입력이 유효하면 오른쪽을, 왼쪽 입력이 유효하면 왼쪽을 바라본다.
- 위치가 실제로 바뀌면 현재 바라보는 방향의 이동 애니메이션을 반복 재생한다.
- 좌우 방향이 바뀌면 그 방향의 애니메이션으로 즉시 전환한다.
- 시트에 좌우 동작이 각각 있으면 해당 프레임을 사용한다. 한 방향만 있으면 좌우 반전으로 반대 방향을 표현한다.
- 표시 방향과 이동 벡터는 별도로 관리한다. 경계에서 수평 입력이 막혀도 유효한 좌우 입력 방향은 반영한다.

### FR-05. 세로 이동 시 방향 유지

- 위/아래 이동만 입력되면 직전에 바라보던 좌우 방향을 유지한다.
- 좌우 입력이 상쇄된 상태에서 세로 이동하는 경우에도 마지막 방향을 유지한다.
- 대각선 이동에서는 유효한 좌우 입력으로 방향을 결정한다.
- 이동을 멈춘 뒤에도 마지막 방향을 유지한다.

### FR-06. 화면 경계 제한

- 좌표는 캐릭터 중심을 기준으로 관리한다.
- 캐릭터가 그려지는 영역의 절반 크기를 고려해 중심 좌표를 제한한다.
- 표시 너비가 `W`, 높이가 `H`이면 `W/2 ≤ x ≤ 화면너비−W/2`, `H/2 ≤ y ≤ 화면높이−H/2`를 만족하게 한다.
- 프레임별 크기가 다르면 전체 사용 프레임의 최대 표시 크기로 경계를 계산해 동작 전환 시 잘림을 방지한다.
- 이동할 좌표를 계산한 뒤 경계 안으로 보정한다. 한 축이 막혀도 다른 축의 이동은 허용한다.
- 화면보다 큰 표시 크기는 배율을 조정해 화면 안에 들어오도록 한다.

### FR-07. 프레임 표시 및 시간 처리

- IDLE 및 이동 동작의 프레임 좌표와 개수를 실제 시트에서 확인한다. 기존 예제의 100×100 셀과 8프레임은 검증 없이 모든 동작에 적용하지 않는다.
- pico2d의 왼쪽 아래 원점에 맞춰 잘라낼 영역을 정의한다.
- 프레임 간격은 초기 0.1초로 설정하고 상수로 조정할 수 있게 한다.
- 애니메이션 상태 또는 표시 방향이 바뀌면 프레임 인덱스와 누적 재생 시간을 초기화한다. 같은 상태에서는 프레임 재생을 이어간다.
- 캐릭터의 원본 비율과 공통 표시 기준점을 유지해 상태 전환 시 위치가 과도하게 흔들리지 않게 한다.
- 이동 시간과 애니메이션 시간을 경과 시간으로 처리하고, 이벤트 처리를 막는 긴 대기는 사용하지 않는다.

### FR-08. 종료

- 창 닫기 또는 Escape 입력으로 종료한다.
- IDLE 상태와 이동 상태 모두에서 종료 입력을 처리한다.
- 종료 및 로딩 실패 시 열린 캔버스를 정리한다.

## 4. 단일 파일 설계

`move_charcter_viewer.py`는 다음 순서로 구성한다.

1. 화면 크기, 이동 속도, 표시 크기/배율, 프레임 간격 상수
2. IDLE/이동 및 좌우 방향별 프레임 메타데이터
3. 이미지 로딩 및 초기화
4. KEYDOWN/KEYUP, 포커스 해제, 종료 이벤트 처리
5. 이동 벡터 계산과 경계 보정
6. 실제 이동 여부 및 바라보는 방향에 따른 애니메이션 상태 결정
7. 경과 시간에 따른 프레임 갱신
8. 배경과 캐릭터 렌더링
9. 메인 루프 및 정리

관리할 상태는 실행 여부, 눌린 방향키 집합, 중심 좌표 `x/y`, 바라보는 방향, IDLE/이동 구분, 프레임 인덱스, 누적 프레임 시간이다.

한 루프에서 이벤트 처리 → 이동 후보 좌표 계산 → 경계 보정 → 실제 위치 변화 확인 → 상태·방향 전환 → 프레임 갱신 → 배경 및 캐릭터 그리기를 진행한다. 수평 입력으로 방향을 먼저 결정하고, 보정된 좌표가 이전 좌표와 다른지에 따라 이동/IDLE을 결정한다.

## 7. 구현 전 확정할 사항

- `animation_sheet.png`의 IDLE/이동 동작 위치, 좌우 방향별 프레임 수 및 순서
- 실제 프레임 크기와 캐릭터 표시 크기/배율
- 화면에 표시한 배경과 캐릭터를 기준으로 필요한 이동 속도·프레임 간격 조정

프레임 좌표와 표시 배율은 이미지 분석 후 확정한다. Python/pico2d, 지정된 단일 파일과 이미지, 방향키 이동, IDLE/이동 전환, 세로 이동 시 마지막 좌우 방향 유지, 화면 경계 제한, 최소 20회의 한국어 개발 커밋은 고정 요구사항이다.

## 8. 구현 시 확정한 값

- 실제 스프라이트 크기는 802×402픽셀이다. 위에서부터 오른쪽 IDLE, 왼쪽 IDLE, 오른쪽 이동, 왼쪽 이동으로 구성된다.
- 각 동작은 100×100픽셀 셀 8개를 사용한다. 왼쪽 아래 기준 행 좌표는 각각 302, 202, 102, 2이다.
- 표시 배율은 1.5배로 정해 셀을 150×150픽셀로 표시한다. 표시 배율은 화면보다 커지지 않도록 제한한다.
- 현재 경계 기준은 중심 좌표 `75 ≤ x ≤ 725`, `75 ≤ y ≤ 525`이다. 투명 여백을 포함한 셀 전체가 화면 안에 남도록 제한한다.
- 이동 속도는 초당 200픽셀, 프레임 간격은 0.1초이다.
- 포커스 이벤트 처리를 위해 pico2d가 제공하는 SDL 이벤트 API로 직접 폴링한다.
- 자동 테스트 및 뷰어 실행은 수행하지 않았다. 수동 확인 결과는 `DEVELOPMENT.md`의 항목에 따라 사용자 확인 후 기록한다.
