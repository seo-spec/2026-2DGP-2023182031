# 소닉 스프라이트 애니메이션 뷰어 개발 문서
## 1. 목적

`sonic-sprite.png`에 포함된 모든 애니메이션을 순서대로 감상할 수 있는 뷰어를 만든다. Python과 pico2d를 사용하며, 작은 스프라이트를 확대해 각 동작을 명확히 확인할 수 있게 한다.

이 문서는 같은 폴더의 `PRE_PRD.md`와 이후 추가된 요구사항을 기준으로 작성한다. 화면 크기는 1200×800픽셀을 기준으로 한다. 프레임 속도와 동작별 프레임 좌표 등 미정인 세부 사항은 아래 개발 기준에 따라 구현 과정에서 결정한다.

## 2. 개발 범위와 산출물

| 항목                      | 요구사항                                        |
| ------------------------- | ----------------------------------------------- |
| 언어 및 그래픽 라이브러리 | Python, pico2d                                  |
| 화면 크기                 | 가로 1200픽셀 × 세로 800픽셀                    |
| 실행 코드                 | `Labs/LEC09/sonic_sprite_viewer.py` 단일 파일 |
| 이미지                    | 같은 폴더의 `sonic-sprite.png`                 |
| 재생 범위                 | 스프라이트 시트에 포함된 모든 애니메이션        |
| 개발 방식                 | 단계별 구현과 검증, 최소 20회의 개발 커밋       |
| 커밋 메시지               | 모든 개발 커밋 메시지를 한글로 작성             |

애니메이션 메타데이터와 재생 로직은 실행 코드 안에 정의한다. 별도 Python 모듈이나 외부 설정 파일은 추가하지 않는다. 프레임 좌표는 LEC08의 다른 이미지에 사용한 값을 그대로 복사하지 않고 실제 `sonic-sprite.png`를 분석해 결정한다.

## 3. 기능 요구사항

### FR-01. 이미지 로딩 및 초기화

- pico2d 캔버스를 `open_canvas(1200, 800)`으로 열고 `sonic-sprite.png`를 로딩한다.
- 이미지 경로는 실행 파일의 위치를 기준으로 계산한다.
- 파일이 없거나 로딩에 실패하면 원인을 알 수 있는 메시지를 출력하고 종료한다.

### FR-02. 전체 애니메이션 정의

- 구현 전에 시트를 확인하고 동작 이름, 재생 순서, 프레임 목록을 작성한다.
- 각 프레임은 잘라낼 영역 `(x, y, width, height)`로 정의한다.
- 시트의 모든 애니메이션이 재생 목록에 포함되어야 한다. 동작의 정확한 수와 이름은 이미지 분석 후 확정한다.
- pico2d의 이미지 좌표 기준에 맞춰 좌표를 정의하고, 인접 동작이나 배경이 잘못 잘리지 않도록 확인한다.

### FR-03. 동작별 5회 반복

- 현재 동작의 첫 프레임부터 마지막 프레임까지 재생하면 1회로 센다.
- 같은 동작을 정확히 5회 재생한다.
- 프레임 수가 다른 동작도 동일한 반복 횟수 기준을 적용한다.

### FR-04. 동작 간 1초 대기

- 한 동작의 5회 반복이 끝나면 1초 동안 대기한다.
- 대기 중에는 마지막 프레임을 유지한다. 이는 초안의 휴식 시간을 표현하기 위한 개발 기준이다.
- 마지막 동작 뒤에도 1초 대기하고 첫 동작으로 돌아간다.
- 대기 중에도 창 닫기와 종료 입력에 반응한다.

### FR-05. 전체 목록 무한 반복

- 정해진 순서로 전체 동작을 재생한다.
- 마지막 동작의 대기가 끝나면 첫 동작을 반복 횟수 0부터 다시 재생한다.
- 사용자가 종료할 때까지 순환한다.

### FR-06. 확대 표시

- 스프라이트가 잘 보이도록 원본보다 확대해 캔버스에 표시한다.
- 원본 프레임의 가로·세로 비율을 유지한다.
- 동작 사이에 위치가 과도하게 흔들리지 않도록 공통 기준점에 맞춰 그린다.
- 최대 크기 프레임도 1200×800픽셀 화면 밖으로 잘리지 않도록 확대 배율을 결정한다.

### FR-07. 종료 처리

- 창 닫기 또는 Escape 입력으로 실행을 종료한다.
- 재생 및 대기 상태 모두에서 이벤트를 처리한다.
- 종료 시 캔버스를 닫는다.

## 4. 단일 파일 내부 설계

다음 구성 요소를 `sonic_sprite_viewer.py` 안에 순서대로 배치한다.

1. 창 크기(1200×800), 확대 배율, 프레임 간격, 반복 횟수(5), 대기 시간(1초) 상수
2. 동작별 프레임 메타데이터와 명시적인 재생 순서
3. 초기화 및 이미지 로딩
4. 이벤트 처리
5. 경과 시간 기반 재생 상태 갱신
6. 현재 프레임 그리기
7. 메인 루프 및 종료 처리

재생 상태는 현재 동작 인덱스, 프레임 인덱스, 완료된 반복 횟수, 재생/대기 구분, 누적 시간을 관리한다. 마지막 프레임의 표시 시간이 끝나면 반복 횟수를 올리고, 5회가 되면 대기 상태로 전환한다. 대기 시간이 1초에 도달하면 다음 동작의 첫 프레임으로 이동한다.

프레임 간격은 상수로 조정할 수 있게 한다. 최초 값은 구현 시 시각적으로 검증해 결정한다. 긴 정지 호출로 1초를 기다리지 않고, 메인 루프에서 경과 시간을 확인해 이벤트 처리를 유지한다.

## 5. 단계별 구현 및 커밋 계획

각 단계는 실제 변경과 확인 결과를 포함한 개발 커밋으로 남긴다. 빈 커밋으로 횟수를 채우지 않는다. 아래 22단계를 기준으로 진행해 최소 20회 요구사항을 충족한다. 이 문서 작성만으로 개발 커밋 요구사항이 완료된 것으로 보지 않는다.

모든 개발 커밋 메시지는 반드시 한글로 작성하고, 해당 단계에서 변경한 내용을 구체적으로 설명한다. 파일명과 라이브러리명 등 기술 식별자는 원문으로 표기할 수 있지만, 설명 문장은 한글로 작성한다. 예: `소닉 스프라이트 이미지 로딩 구현`, `동작별 5회 반복과 1초 대기 처리 추가`.

| 단계 | 구현 및 확인 내용                         |
| ---- | ----------------------------------------- |
| 1    | 단일 파일 진입점과 실행 구조 작성         |
| 2    | pico2d 캔버스 열기·닫기 구현             |
| 3    | 창 닫기 및 Escape 이벤트 처리             |
| 4    | 실행 파일 기준 이미지 경로 구성           |
| 5    | 이미지 로딩 및 실패 처리                  |
| 6    | 원본 시트 표시로 이미지 로딩 확인         |
| 7    | 시트 분석 결과와 전체 동작 목록 정의      |
| 8    | 첫 동작의 첫 프레임 좌표 정의 및 표시     |
| 9    | 비율을 유지하는 확대 표시 구현            |
| 10   | 공통 표시 기준점과 화면 여백 조정         |
| 11   | 첫 동작의 전체 프레임 데이터 정의         |
| 12   | 경과 시간 기반 프레임 전환 구현           |
| 13   | 첫 동작의 1회 재생 경계 확인              |
| 14   | 동작별 5회 반복 및 횟수 관리 구현         |
| 15   | 이벤트 처리가 가능한 1초 대기 구현        |
| 16   | 두 번째 동작의 데이터와 순차 전환 구현    |
| 17   | 나머지 동작의 프레임 데이터 추가          |
| 18   | 전체 동작의 누락과 좌표 오류 검토 및 수정 |
| 19   | 마지막 동작에서 첫 동작으로 순환 구현     |
| 20   | 동작 전환 시 상태 초기화와 경계 처리 보완 |
| 21   | 1200×800 화면에서 확대 배율·프레임 속도 최종 조정 |
| 22   | 전체 순환 및 종료 검증 결과 기록          |

17~18단계는 동작 수가 많으면 여러 커밋으로 나눌 수 있다. 확인만 하는 단계는 확인 결과를 코드 내 설명 또는 개발 기록으로 남겨 추적 가능하게 한다.

## 6. 검증 및 완료 기준

| 검증 항목      | 통과 기준                                                           |
| -------------- | ------------------------------------------------------------------- |
| 실행           | Python과 pico2d가 준비된 환경에서 단일 파일로 창이 열린다.          |
| 화면 크기      | 캔버스 크기가 가로 1200픽셀, 세로 800픽셀이다.                       |
| 이미지 경로    | 다른 작업 디렉터리에서 실행해도 이미지를 로딩한다.                  |
| 동작 포함 여부 | 시트 분석 목록과 구현 목록을 대조했을 때 빠진 애니메이션이 없다.    |
| 프레임 표시    | 프레임 순서가 올바르고 다른 동작 영역이 섞이지 않는다.              |
| 반복 횟수      | 각 동작이 첫 프레임부터 마지막 프레임까지 정확히 5회 재생된다.      |
| 대기 시간      | 5회 완료 후 경과 시간 기준 1초 뒤 다음 동작으로 전환한다.           |
| 전체 순환      | 전체 목록을 최소 두 번 순환하며 상태가 정상적으로 초기화된다.       |
| 확대 품질      | 원본보다 크게 보이며 비율이 유지되고 프레임이 화면에 잘리지 않는다. |
| 종료           | 재생 중과 대기 중 모두 창 닫기 및 Escape에 반응한다.                |
| 실패 처리      | 이미지 누락 시 원인을 알 수 있는 메시지로 종료한다.                 |
| 산출물         | 실행 코드가 `sonic_sprite_viewer.py` 한 파일에 포함된다.           |
| 개발 이력      | 실제 구현 및 검증을 담은 개발 커밋이 최소 20회 존재한다.            |
| 커밋 메시지    | 모든 개발 커밋의 설명이 한글로 작성되어 있다.                       |

## 7. 구현 전 확정할 사항

- 실제 시트에 포함된 동작 수, 동작 이름, 프레임 좌표 및 재생 순서
- 1200×800픽셀 화면에 맞는 확대 배율과 공통 표시 기준점
- 각 동작을 자연스럽게 볼 수 있는 프레임 간격

위 값은 초안에 명시되지 않았으므로 이미지 분석과 실제 실행 확인을 거쳐 정한다. 동작별 5회 반복, 1초 대기, 전체 무한 반복, Python/pico2d 사용, 단일 파일, 최소 20회 개발 커밋 및 한글 커밋 메시지는 고정 요구사항이다.
